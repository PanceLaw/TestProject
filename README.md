# Тестовое задание QA: банковские продукты

Для банковских продуктов тестового задания не использовались и не описывались договора.

## Описание

В проекте реализована архитектура банковских продуктов:

- дебетовая карта;
- валютная дебетовая карта;
- кредитная карта;
- вклад.

Общие параметры банковского продукта:

- название;
- валюта;
- баланс.

Денежные значения хранятся через `BigDecimal`.

## Структура

Основной код:

```text
src/main/java/ru/qa/bank
  exception
  model
  product
    card
    deposit
```

Тесты:

```text
src/test/java/ru/qa/bank
  producttests
    card
    deposit
```

## Архитектура

Базовый контракт банковского продукта описан интерфейсом `BankProduct`.

Общее поведение разделено на интерфейсы:

- `Replenishable` - продукт можно пополнять;
- `Withdrawable` - с продукта можно списывать средства;
- `ClosableProduct` - продукт можно закрыть.

Общие поля и базовая валидация вынесены в `AbstractBankProduct`.

Общая логика карт вынесена в `AbstractCard`.

Классы карт лежат в пакете:

```text
ru.qa.bank.product.card
```

Класс вклада лежит в пакете:

```text
ru.qa.bank.product.deposit
```

## Продукты

### DebitCard

Дебетовая карта поддерживает:

- пополнение;
- списание;
- запрос баланса.

Списание невозможно, если на карте недостаточно средств.

### CurrencyDebitCard

Валютная дебетовая карта наследует поведение обычной дебетовой карты.

Для валютной карты запрещена валюта `RUB`. Используются `USD` и `EUR`.

### CreditCard

Кредитная карта поддерживает:

- пополнение;
- списание;
- запрос баланса;
- запрос задолженности;
- запрос процентной ставки;
- запрос кредитного лимита;
- запрос доступных средств.

При списании сначала расходуется собственный баланс. Если его недостаточно, недостающая сумма переходит в задолженность.

Списание невозможно, если операция превышает кредитный лимит.

При пополнении кредитной карты сначала погашается задолженность. Остаток суммы после погашения увеличивает баланс.

### Deposit

Вклад поддерживает:

- пополнение;
- запрос баланса;
- закрытие.

При закрытии вклад возвращает сумму выплаты, переводит баланс в `0` и получает статус закрытого продукта.

Пополнение закрытого вклада и повторное закрытие запрещены.

## Исключения

В проекте используются доменные исключения:

- `InvalidAmountException` - некорректная сумма;
- `InsufficientFundsException` - недостаточно средств или превышен кредитный лимит;
- `ProductClosedException` - операция невозможна, потому что продукт закрыт.

Сообщения исключений написаны на английском языке.

## Расширяемость

Архитектура рассчитана на добавление новых продуктов без изменения существующих классов.

Например, новый накопительный счет может наследоваться от `AbstractBankProduct` и реализовать только нужные интерфейсы:

```java
public class SavingsAccount extends AbstractBankProduct implements Replenishable, Withdrawable {
    // логика нового продукта
}
```

Если новый продукт нельзя пополнять, он не реализует `Replenishable`.

Если продукт нельзя закрывать, он не реализует `ClosableProduct`.

## Тесты

Unit-тесты написаны на JUnit 5.

Для групп проверок используются soft assertions из AssertJ.

Покрыты сценарии:

- создание банковских продуктов;
- пополнение;
- списание;
- недостаток средств;
- превышение кредитного лимита;
- расчет задолженности кредитной карты;
- расчет доступных средств кредитной карты;
- закрытие вклада с возвратом суммы выплаты;
- запрет пополнения закрытого вклада;
- запрет повторного закрытия вклада;
- валидация названия, валюты, начального баланса и сумм операций.

## Запуск

Запустить тесты можно командой:

```bash
mvn test
```
